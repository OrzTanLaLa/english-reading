# 排障方法论（这次学到的最硬的一条）

## 核心原则：卡 20 分钟就换方法

第 6 轮盲试坐标那次，真正解决问题的是「**打印真实数值**」，不是再试一组参数。

### 症状 → 该做什么

| 症状 | 第一动作 | 不要做什么 |
|---|---|---|
| 点击没反应 | `uitest dumpLayout` 查控件真实 bounds | 靠截图目测坐标 |
| API 返回不合理 | **打印入参与返回值**，和文档对照 | 改参数再试 |
| 结果显示像「另一个东西」 | **核对输入是不是你以为的那个** | 怀疑模型/框架 |
| 编译报错看不懂 | 直接跑 hvigor 看完整输出 | 只信脚本打印的一行 |
| 构建/装机偶发失败 | 先看是不是「新增文件没全量」 | 反复重试 |

## 三个具体教训

### 1. 「模型答错了」先怀疑输入
CQR 探针返回「整句」而不是某个词，我以为是提示词问题。
实际是拿错了录音文件（`a01.wav` ≠ `c01.wav`）。**换成正确文件后结果与基准完全一致**。

### 2. 「坐标对不上」先分清三套坐标系
一个点击事件牵涉：屏幕 px（截图/`uitest`）、组件内 vp（`ClickEvent.x/y`）、
排版引擎 px（`getRectsForRange` 返回值）。混用任何两套都会「差一半」。
**做法**：打印 `vp2px(1)` 的小数、一个已知词的矩形、点击事件的原始坐标，
三行数字摆在一起就能看出比例。

### 3. 「白屏 401」是构建问题不是代码问题
`Failed to load the content {"code":401}` 出现时不要查路由代码，
先查**是不是新加了文件却走了增量构建**。官方文档明确写 Hot Reload 不支持新增文件。

## 验证层级（按可信度）

1. **设备上跑通 + 截图 + 数字**（最高）；
2. 探针页跑通（不接主流程）；
3. 单元级脚本（Python 侧验证算法/接口）；
4. 我「认为能跑」（最低，基本不算验证）。

## 省钱式验证

- 能用**缓存**的就别重算（音频、OCR 输出、模型对比结果）；
- 能用**已有产物**就别重新请求（`artifacts/b2-final/model-outputs/` 里有 6 个模型 × 5 张图的输出）；
- 提示词类改动先用**内置 wav/图片**验证，别用麦克风现场录。

## 文档化的时机

**一次验证成功之后就写**，不要攒到后面：
- 成功的参数（`sample_rate=16000`、`word_timestamp_enabled=true`）；
- 失败的路径（哪些方案被否决、为什么）；
- 版本门槛（API 24+、API 26 才有）。
