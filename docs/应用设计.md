# 应用设计（人机共用）

> 这份文件描述**产品是什么、长什么样、怎么运作**，不写代码细节。
> 实现细节在 `docs/agent/project/implementation.md`；进度与待办在 [`待办清单.md`](待办清单.md)。
> 设计有变更时**必须更新本文件**（UI、流程、规则、数据结构、成本口径都算）。

---

## 1. 一句话

把英语课本**拍下来**，App 用云端模型把文字读出来，再**逐词朗读并高亮**；读到哪里停下来问一句「这个词什么意思」，App 用语音回答，并把这个词记进本课的**生语汇**。

## 2. 目标用户与场景

- 用户：需要精读英语课文的学生（本项目主要使用者：一位中学生）。
- 场景：桌面上摊开课本，平板立在旁边；拍照导入 → 听读 → 遇到不懂的词随时提问。
- 关键约束：**手要用来翻书**，所以提问必须是语音；**看的是英文原文**，所以高亮要跟着声音走。

## 3. 核心流程

```
① 拍照/选图  →  ② OCR 出正文（可校对）  →  ③ 合成语音  →  ④ 逐词朗读 + 高亮
                                                              ↓
                                                    ⑤ 语音提问（随时）
                                                              ↓
                                            ⑥ 中文回答（朗读）+ 写入生语汇
```

- **③ 只在需要时发生**：文本与音色没变就复用缓存，不重复计费。
- **② 之后先给用户看文本**，确认无误再点「去朗读」才触发合成（省钱，也避免读错）。

## 4. 页面

> 5 个页面。导航：文库 ⇄ 扫描 → 编辑页 → 朗读页；生语汇页从文库页 ⋮ 进入。
> 平板以横屏为主，单列限宽（max 900vp 居中）。

### 4.1 文库页（首页）

```
┌─────────────────────────────────────────────┐
│  文库                                    (＋)│  ← 系统标题栏
│  ┌─────────────────────────────────────┐    │
│  │ Unit 3  Grit                  ⋮    │    │
│  │ 4 页 · 3 分 34 秒 · 昨天            │    │
│  └─────────────────────────────────────┘    │
│                                             │
└─────────────────────────────────────────────┘
```

- 行内容：标题 + 副标题「页数 · 音频时长 · 相对时间」。
- 点行进朗读页（没有音频就进去后自动合成）。
- **＋ 放在标题栏右侧**（系统标题栏的菜单图标：`sys.symbol.plus`，自带**圆形底板**）→ **编辑页（新建）**。
  扫描只在编辑页里通过「添加图片」进入——先有「一门课」，再往里加图片，比「先扫描再建课」少一步且不会建出空课。
- 空状态：「还没有课文 / 点右上角 ＋ 新建课文」。

**⋮ 动作面板**

| 动作 | 说明 |
|---|---|
| 编辑 | 进入编辑页（改标题、增删排序图片、识别、改全文） |
| 生语汇 | 打开本课生语汇页（见 4.6） |
| 删除 | 二次确认「将删除文本、原图、音频和生语汇」 |

> 「重新生成音频」已移除（2026-10-23）：没实现，日常也用不到——改文本/换音色会让 `textHash` 失配，进朗读页自动重合成。

### 4.2 扫描页

**用系统的文档扫描控件**（`DocumentScanner`），不自己画取景框：自动找边、裁剪、透视校正、连拍、旋转删除都由系统提供。

- **手动快门**（`ShootingMode.MANUAL`）：试过自动模式，会对着桌面连拍 10 张废图。
- 最多 10 张；支持从**图库**选图（图库流程见下方注意）。
- 编辑页签保留「删除」「旋转」，去掉其余。
- 点「完成」→ 进入 **4.3 编辑页**（系统控件不允许被浮层遮挡，所以必须跳页）。
- 点「✕」取消 → 回文库页。

> 图库要两步：选择器点「完成」只是加入列表，还要点右上角**带角标的保存图标**才真正返回结果。

### 4.3 编辑页（替代原「确认页」与原图查看；确认页已删除）

```
┌─────────────────────────────────────────────┐
│ (‹) 未命名 2026-10-21 22:15          (保存)│  ← 圆形底板图标 + 文字按钮
│                                             │
│  标题 ┌───────────────────────────────────┐ │
│       │ 给这篇课文起个名字                │ │
│       └───────────────────────────────────┘ │
│  ┌────┐┌────┐┌────┐                        │
│  │ 图 ││ 图 ││ 图 │   共 3 张              │
│  └────┘└────┘└────┘                        │
│                                             │
│           [ 开始识别 ]                      │
└─────────────────────────────────────────────┘
```

- 标题为空 → 自动用「未命名 YYYY-MM-DD hh:mm」，不阻塞流程。
- **两种进入方式**：① 扫描页「保存」后自动进来（新建课程）；② 文库页 ⋮ →「编辑」（编辑已有课程）。
- 标题下方**左右分栏**：左侧窄的图片列表（约 20% 宽，**只显示图片**，上下滚动、长按拖拽排序、左滑「删除」），右侧上方是「添加图片」「识别」两个按钮、下方是宽的文本编辑框。
- 一张页面上完成全部编辑：标题、图片、识别、全文编辑、保存。
- 图片是**竖排列表**（每行一张缩略图 + 序号），左滑滑出「删除」；长按拖动排序。
- 加图片走「添加图片」按钮（`List` 没有「添加项按钮」这种 API，只能自己放一个）。
- **识别 = 全文替换**：点了就用识别结果整体覆盖全文框，人工再改。
- 「保存」：标题改名；全文有变 → 写文本并**丢弃旧音频**（下次进朗读页重新合成）。
- 识别失败 → 进度文字标红，全文框内容保留。

### 4.4 朗读页

```
┌────────────────────────────────┬──────────────────┐
│ ‹ 未命名 2026-10-21 22:15      │  [▶]   [🎤]      │
│                                ├──────────────────┤
│ valuable because it can track  │ 问：grit 什么意思 │
│ how often publications review  │ 答：毅力……        │
│ books by women, but what it    │                  │
│ can't track is how reviewers   │ 问：这句怎么翻译   │
│ then treat women's work: …     │ 答：这句话的意思是 │
│                                │ ……（可滚动）      │
│                                ├──────────────────┤
│                                │ [输入问题…    ]  │
└────────────────────────────────┴──────────────────┘
        左 70%（正文 + 高亮）        右 30%
```

**顶栏**：系统标题栏（`HdsNavigation`）——左圆形返回、中标题、右侧两个文字胶囊按钮：
「显示原文 / 显示读法」切换视图、「**语汇录**」直接进本课生语汇页（不用退回文库再点 ⋮）。

**左栏：正文与高亮**

- 按段落渲染原文，`fontSize 19`、`lineHeight 32`；点任意词 → 从那词开始播放。
- 当前词是浅蓝底圆角块（不改文字样式，所以不重排）；滚动自动跟随当前词。
- 手动拖动后暂停跟随，松手 3 秒恢复。

**右栏三块（从上到下）**

1. **按钮行**：并排「播放/暂停」与「提问」，用系统符号图标（`play_fill` / `pause` / `mic_fill`）；
2. **对话区**：一个文本控件、可滚动，按「一问一答」追加；只显示**问**（语音模型给的 `question` 或键盘输入）与**答**（主 Agent 回答），不显示解析过程里的中间产物；
3. **提问输入框**：比对话区矮；回车/点发送提交。

**录音中的按钮变化**

点麦克风开始录音后，**整排只剩两个按钮**（播放键也隐藏——录音时不会有人去点播放）：

```
[ ⏹ ]  [ 取消 ]
 停止     取消
```

- 左：**停止图标**（`sys.symbol.stop_circle_fill`）——结束录音并进入识别；
- 右：**取消**——丢弃本次录音，直接回到麦克风按钮，不发起识别。

**提问的两条路**

| 方式 | 链路 |
|---|---|
| 打字 | 输入框文本 → 主 Agent → 回答追加到对话区 |
| 说话 | 点「提问」录音 → Omni 解析出 `question` → 主 Agent → 回答追加 |

- 提问时**暂停播放**；回答生成后**自动朗读**（端侧 TTS，可点答句上的重听）。
- 不再有「弹出面板」：对话是常驻的，历次问答都在右侧。

**三种播放状态**

| 状态 | 表现 |
|---|---|
| 合成中 | 正文先显示，右栏按钮置灰并显示「语音合成中…」 |
| 合成失败 | 显示「语音生成失败 · 重试」，正文仍可读 |
| 可播放 | 按钮可用，自动定位到上次位置 |

**朗读页没有编辑入口**：改标题/改全文/改图片一律去编辑页。


### 4.5 生语汇页

```
┌─────────────────────────────────────────────┐
│  ‹ 生语汇                             共 7 条 │
│  ─────────────────────────────────────────  │
│  单词  grit      毅力；这里指坚持不懈        │
│    Grit is not simply persistence.          │
│  ─────────────────────────────────────────  │
│  搭配  take for granted   视为理所当然       │
│    We take clean water for granted.         │
│  ─────────────────────────────────────────  │
│  …（可滚动）                                 │
└─────────────────────────────────────────────┘
```

- 页面**直接显示本课 `glossary.yaml` 的原文**（可滚动、可复制），标题栏副标题给「共 N 条」。
  不做解析排版——这份文件是给人看的交付物，原文最有用；解析只用于统计条数与写入。
- 文件格式（根节点序列，元素映射，四键）：

```yaml
- 类型: '单词'
  单词: 'serendipity'
  语境: 'The secret to remembering travel.'
  问题: 'serendipity 什么意思'
  回答: '意外发现美好事物的运气……'
```

- 类型为**搭配**时再多一个 `搭配:` 键（放词组/搭配/句式本身）；类型为**其他**时没有 `单词`/`搭配` 两键。
  （新增两键与提示词的精简，见待办 T7。）

- **「当前词」不进任何模型提示词**（D45）：语音提问解析只给「当前句」，答者也只给全文+当前句+问题。
  理由：用户可能问这一句里的任何词，给当前词反而诱导模型把问题往那个词上靠。
- **提示词里两份文本来源不同**（D44）：
  - `课文全文` = **原文**（`text.txt`，保留括号/破折号，数字原样）；
  - `当前句` = **读法**（词时间戳坐标系里按句号截取，和点击/高亮同一个坐标系）；
  - `问题` = 原样。两份文本逐字对不上没关系，句子顺序一致，模型能自己把当前句对到全文里。
- 暂不做：删除、跳回原句、按单词归类、导出（都记在 7.5「可能要做」）。

### 4.7 全局规则

| 场景 | 表现 |
|---|---|
| 合成失败 | 底部「语音生成失败 · 重试」，文本仍可读 |
| OCR 全部失败 | 留在编辑页，进步文字标红 + 重试 |
| 网络中断 | 顶部胶囊「离线」；已缓存音频仍可播 |
| 鉴权失败 | 弹窗 +「去改 Key」 |
| 相机/麦克风被拒 | 提示 + 降级（改用图库 / 禁用 🎤） |
| **图标** | 图标用系统符号（`sys.symbol.*`）；**带底板的圆形图标按钮用 HDS 标题栏，不自己画圆** |
| **返回** | 标题栏左侧 `chevron_left`，**圆形底板**（HDS 标题栏自带），点击 `router.back()` |
| **标题栏** | 四个产品页统一用 `HdsNavigation` 的 `titleBar`（`mode(Stack)`、内容留 `top: 56`）；扫描页无标题栏 |

## 4.8 版本管理与数据安全（自用，不发布）

- **不发布**：不上架应用市场，继续 debug 签名 + `hdc install -r` 装机。
- **版本号**：`versionCode` 随每次交付递增、`versionName` 语义化（`1.0.0` 起）；文库页标题栏显示 `v<versionName>`。
- **升级只覆盖安装**，绝不卸载；卸载会清空课程数据。
- **数据结构版本** `schemaVersion`：新版本启动时若发现旧数据，**先把 `meta.json`/`glossary.txt`
  备份到 `files/backup_v<old>_<时间戳>/`，再迁移，只迁移不删除**；迁移幂等，重复启动不重复执行。
- 后续提供「导出」（zip 到用户选的位置）作为最终兜底；换机迁移可再上系统备份恢复框架。

### 4.9 设置（三层）

入口：**文库页标题栏 `gearshape` 图标**。

```
设置（卡片分组列表）
├─ 关于            → 关于页（纯文本：版本 / 课程数 / 数据结构版本 / 数据存放说明）
└─ 修改 API Key    → API Key 列表（卡片分组，两项：百炼 / DeepSeek）
                      └─ 点任一项 → 编辑页（一个输入框，标题栏右上「保存」）
```

- 全部用系统设置那种**分组卡片列表**：`ListItemGroup(CARD)` + `ListItem(CARD)` + 行间分割线。
- 每层都是独立页面，返回走标题栏左侧箭头；不弹窗、不用页内浮层。
- API Key 列表每行右侧显示 **已设置 / 未设置**；点进去是编辑页。
- 编辑页：**密码样式**（`type(InputType.Password)` + `showPasswordIcon(true)`）——
  默认显示圆点，末尾**眼睛图标**点一下看明文（控件自带，不用自己做）。
- Key 存在 Preferences（不进代码仓库）；编辑页预填当前值，标题栏「保存」，返回后列表状态即时更新。
- **导出文库数据**：选一个目录 → 生成一个 **zip**（`英语朗读-<时间>.zip`）。
  zip 里每份文本一个目录（目录名 = 课程 id），内容与 App 内完全一致
  （`meta.json`/`text.txt`/`images/`/`audio.pcm`/`words.json`/`sentences.json`/`glossary.yaml`）；
  解开后把各目录拷回 `files/course/` 即可恢复。
  实现：`picker.select(FOLDER)` → `new fileUri.FileUri(uri).path` → `fs.copyFileSync(zip, 路径/名字)`。

### 4.10 朗读文本预处理

- 合成前调用 `QwenTts.normalizeForTts()`：把 **em dash / en dash / figure dash / horizontal bar / minus**
  （U+2014/2013/2012/2015/2212）统一换成 `, `，并收拾多余空格；**不动单词内的连字符 `-`**。
- 原因：`qwen-audio-3.1-tts-flash` 遇到 `—` 朗读异常；官方**没有标点支持清单**，
  兜底手段是 `hot_fix`（指定符号/缩写读法）与 `language_hints`（目标语言）。
- 只影响送进 TTS 的文本：显示仍用原文 `splitSentences(text)`，`words.json` 只存词与时间，高亮不受影响。

## 5. 内容与数据规则

- **一门课 = 一个文件夹**：原图、正文、音频、词时间戳、生语汇。
- 只保留**当前音色**的音频；换音色或改文本都会让缓存失效并重新合成。
- OCR 输出规则（由提示词保证，代码只兜底）：
  - 只转写正文；去掉页眉页脚、页码、水印、页边注释与生词表、单词后的上标注释编号；
  - **去掉段首的段落编号/序号**（`1`、`11`、`1.`、`One`、`Two`、`I.`、`①`）——
    编号会被 TTS 念成 "one"/"two" 插进正文；
  - **按段落输出**：段落之间**必须空一行**，段落内部不换行；
  - 保留原文标点、大小写与文章标题；段内的普通数字（`1990s`、`10,287`）不动。

## 6. 语音提问的规则

- 用户用中文提问（"这个词什么意思""这句怎么理解"），系统输出中文解释。
- 判断「问的是哪一句/哪个词」时，**以当前播放位置为上下文**；用户说「这个/这句」指当前句。
- 提问解析由**音频直接进模型**完成（不是先转文字再理解），因为指代判断需要上下文。
- **键盘输入的问题不经过 Omni**：它本来就是文字，直接交给答者 LLM。
- **一次 LLM 调用，没有 Agent 工具循环**：模型只回一个 **JSON**（类型 + 回答 + 单词/搭配），**写生语汇由代码做**。
- **不查本地词典**：释义完全由 LLM 给出（D33，本地 WordNet 已删除）。
- 模型输出用 **JSON**（`response_format=json_object`，服务端保证合法），文件仍写 YAML（D34）。
- 类型只有三种：**单词 / 搭配 / 其他**（问单词→单词；问词组、搭配、句式→搭配；否则→其他）。
- 右侧对话区只记「问」与「答」；解析过程（surface / intent / 理解）不写进对话。
- **不做置信度打分**：把模型对问题的理解原样显示给人看，由人判断有没有听错。
- 回答要短、口语化、面向学生。**问单词/搭配时按三部分写**：先简洁回答问题 → 那句话的中文翻译 →
  若是引申义再说原义并给例句（不是引申义就不写）；全文单行纯文本，**不标序号**。
- 被问到词/短语/句式的意思时**写入本课生语汇**。

## 7. 成本口径

| 项 | 量级 | 说明 |
|---|---|---|
| OCR | ≈0.02 分/页 | 每次导入 |
| 朗读合成 | ≈0.39 分/篇 | 446 字符/25 秒实测；**缓存命中则为 0** |
| 提问解析 | 按音频时长 | 一句话通常 2–4 秒 |
| 回答朗读 | 0 | 用端侧 TTS（免费离线） |

设计取向：**能缓存就不重算，能让用户先确认就不提前花钱。**
